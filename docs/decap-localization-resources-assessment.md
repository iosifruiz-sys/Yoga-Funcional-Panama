# Техническое заключение: ES/RU/EN и будущие Recursos

Дата: 2026-10-23. Анализ текущей архитектуры; перечисленные ниже изменения не реализованы.

## Текущая реструктуризация CMS

Шесть коллекций главной объединены в `homepage` / `Página principal` типа `files`. Все 16 существующих документов, их идентификаторы, пути и полные определения полей сохранены. Общие документы `classes_links`, `schedule_classes`, `about_photo`, `contact_links` остаются общими для ES/RU. `Blog ES` и `Blog RU` сохранены без изменений. Данные не перемещались и не мигрировались.

Коллекция `files` позволяет каждому документу иметь собственный путь и набор полей; файлы должны существовать в ветке backend: [документация Decap](https://decapcms.org/docs/collection-file/).

Изменятся внутренние адреса редактора: ссылки на старые коллекции следует заменить ссылками на `homepage`; идентификаторы документов прежние. Backend по-прежнему указывает на `main`: проверка редактирования на PR-preview без изоляции backend может записать данные в production. При проверке не нажимать Save/Publish. Если имеются активные редакторские черновики или внешние интеграции со старыми именами коллекций, проверить их до слияния.

## Расширение до ES/RU/EN

Сейчас `src/i18n.ts` задаёт только `es | ru`, а `localizedPath` распознаёт лишь префикс RU. Маршруты заданы явно в `src/pages`; определение языка и slug статьи в `src/lib/blog.ts` также рассчитано на два языка. `translationSlug` связывает только одну пару переводов. Header, layouts, теги, sitemap и RSS требуют отдельной проверки при добавлении третьего языка. Простого добавления EN в CMS недостаточно.

Рекомендуемый отдельный этап:

1. Сохранить существующие ES URL в корне и RU URL под `/ru/`; EN проектировать под `/en/`, без перемещения существующих файлов.
2. Ввести явное соответствие языка префиксу и словарю; заменить двоичные ES/RU условия в маршрутизации, переключателе языка, метаданных и структурированных данных.
3. Добавлять `en.json` для разделов главной только после подготовки контента и схем. Не распространять автоматически общие ES/RU ссылки и расписание на EN без решения владельца.
4. Для статей проектировать устойчивый идентификатор группы переводов и поиск по языку. Существующее `translationSlug` поддерживать переходно; миграцию согласовать отдельно. EN статьи хранить отдельно под `src/content/blog/en`, с собственной CMS-коллекцией; исключить их из ES выборки.
5. Выдавать canonical, hreflang и переключатель только для реально опубликованных переводов; согласовать fallback для отсутствующих переводов. Проверить sitemap, RSS, теги, изображения и все языковые ветки.
6. До выпуска проверить главную, списки, статьи и теги на трёх языках и двух классах экранов. Не менять URL и визуальный baseline ES/RU ради локализации.

Astro поддерживает языковые префиксы и default locale: [официальная документация](https://docs.astro.build/en/guides/internationalization/). Внедрять встроенный i18n следует отдельным решением после сверки с установленной версией Astro; это не обязательная часть текущей реструктуризации.

## Будущие Recursos

Recursos следует проектировать отдельно от главной и блога. До разработки определить, это библиотека файлов, самостоятельные материалы или каталог внешних ссылок; нужны ли страницы деталей, категории и переводы.

Для повторяющихся материалов подходит отдельная Astro content collection с валидируемой схемой и отдельными CMS folder-коллекциями по языкам. Предлагаемые данные: устойчивый ID, язык, заголовок, описание, тип ресурса, целевой URL либо файл, необязательная обложка с alt, категории, draft и группа переводов. Требовать ровно один источник — файл или URL; публичные загрузки должны быть намеренно общедоступными. Проверять ссылки и доступность файлов при сборке.

Если нужен редактируемый вводный текст каталога, позднее добавить отдельные ES/RU (и только после запуска EN — EN) документы типа `files`. URL каталога и деталей согласовать заранее, не затрагивая существующие маршруты блога. Переиспользовать существующее оформление без его изменения.

Сейчас коллекции, страницы, данные и маршруты Recursos не создаются. EN также не внедряется.
